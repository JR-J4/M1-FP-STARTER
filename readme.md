# Криптоаналізатор шифру Цезаря

Підсумковий проєкт модуля «Java Syntax»** курсу JavaRush студентки Чіпець Марії.

## Про проєкт

Цей проєкт демонструє реалізацію **шифру Цезаря** на Java з трьома режимами роботи.

### Що таке шифр Цезаря

Найдавніший і найпростіший шифр підставлення: кожну літеру відкритого тексту замінюють на літеру, що стоїть на певне число позицій далі в алфавіті (це число називають **ключем**). Наприклад, з ключем 3: «A» → «D», «B» → «E», «C» → «F». Розшифрування — той самий зсув у зворотному напрямку.

### Що робить програма

- **Шифрування** — перетворює відкритий текст у шифротекст з вибраним ключем. Результат — файл з міткою `[ENCRYPTED]` в імені.
- **Розшифрування** — обернена операція, потребує знання ключа. Результат — файл з міткою `[DECRYPTED]`.
- **Перебір ключів (brute force)** — автоматичний криптоаналіз: програма сама знаходить правильний ключ і відновлює оригінальний текст з шифру, не отримуючи ключ ззовні.

### Що було використано під час створення програми

- **Базовий синтаксис Java:** класи, методи, поля, конструктори, enum'и, цикли, умови.
- **Робота з рядками і колекціями:** `String`, `StringBuilder`, `ArrayList`, `Collections.rotate`.
- **Файловий I/O:** `java.nio.file.Path`, `Files.readString`, `Files.writeString`.
- **Обробка винятків:** `try-catch`, користувацькі помилки.
- **Розбір аргументів командного рядка** (без зовнішніх бібліотек).
- **Поняття одиничного тестування:** як читати тести, як TDD допомагає вести розробку.

## Особливості проєкту

* **Модифікований шифр Цезаря:** Замість класичного пошуку індексів у статичному масиві-алфавіті, логіку оптимізовано за допомогою прямої роботи з ASCII-кодами символів. Для збереження регістру тексту обробка великих (`A-Z`, коди 65–90) та малих (`a-z`, коди 97–122) літер відбувається окремо.
* **Локалізація:** Проєкт повністю орієнтований на роботу з однією мовою, без використання українського алфавіту.
* **Покриття тестами:** У зв'язку зі зміною логіки шифрування та обмеженням мовного діапазону, 3 тести були тимчасово вимкнені за допомогою анотації `@Disabled`.
* **Труднощі:** Модуль автоматичного підбору ключа (Brute Force) дався важко. При його створенні використано принцип **Dependency Injection (Впровадження залежностей)**. Клас приймає вже сконфігуровані об'єкти через конструктор.

## Інтерфейс командного рядка

```
-e   шифрування (encrypt)
-d   розшифрування (decrypt)
-bf  перебір ключів (brute force)
-k   ключ — ціле число зі знаком; обов'язковий для -e і -d
-f   шлях до вхідного файлу
```

Приклади запуску:

```bash
java -jar target/J4-M1-FP-1.0-SNAPSHOT.jar -e -k 5 -f /path/to/file.txt
java -jar target/J4-M1-FP-1.0-SNAPSHOT.jar -d -k 5 -f "/path/to/file [ENCRYPTED].txt"
java -jar target/J4-M1-FP-1.0-SNAPSHOT.jar -bf -f "/path/to/file [ENCRYPTED].txt"
```
